## 2. Admin App Structure

### 2.1 Layout Shell
```
+--------------------------------------------------------------+
| Topbar: logo | global search (products/orders/customers) | user menu |
+----------+---------------------------------------------------+
| Sidebar  |  Content area (page content)                     |
| (below)  |                                                   |
+----------+---------------------------------------------------+
```
- Sidebar navigation groups:
  - **Overview**: Dashboard, Analytics
  - **Catalog**: Products, Categories, Brands, Import, Media
  - **Content**: CMS Sections, Theme Settings, Navigation, Pages, Blogs
  - **Sales**: Orders, Discount Codes
  - **Customers**: Customers, Abandoned Carts
  - **System**: Users & Roles, Email Log
- Topbar: global search across products/orders/customers, user menu (profile, logout)
- Role-gated routes: guard redirects to a 403 screen when the user lacks the permission

### 2.2 Route Map & RBAC Permission Map

| Admin page | Route | Required permission(s) |
|---|---|---|
| Dashboard | `/dashboard` | `dashboard.read` |
| Analytics | `/analytics` | `analytics.read` |
| Products | `/products`, `/products/[id]` | `product.read` / `product.write` |
| Categories | `/categories` | `category.read` / `category.write` |
| Brands | `/brands` | `brand.read` / `brand.write` |
| Import | `/import` | `import.write` |
| Media | `/media` | `media.read` / `media.write` |
| CMS Sections | `/cms/sections` | `cms.write` |
| Theme Settings | `/cms/theme` | `cms.write` |
| Navigation | `/cms/navigation` | `cms.write` |
| Pages | `/cms/pages` | `cms.write` |
| Blogs | `/cms/blogs` | `cms.write` |
| Orders | `/orders`, `/orders/[id]` | `order.read` / `order.write` |
| Discount Codes | `/discounts` | `discount.write` |
| Customers | `/customers`, `/customers/[id]` | `customer.read` |
| Abandoned Carts | `/carts/abandoned` | `customer.read` |
| Users & Roles | `/users`, `/roles` | `user.write` |
| Email Log | `/emails` | `notify.read` |

Permission slugs follow the pattern `{resource}.{action}` (read/write), resolved from `roles` → `role_permissions` → `permissions` at request time (never cached longer than the JWT lifetime; permission changes take effect on the next API call).

## 3. Admin Screens & UX (per page)

> For each screen: purpose, layout, key UI elements, forms/fields, interactions. Acceptance criteria live in `5.Features.md` §B* — referenced, not repeated.

### 3.1 Dashboard
- **Layout:** 4 KPI cards top row, revenue/page-view chart, recent orders table, top products table
- **UI elements:** date-range picker (7/30/90d presets), KPI cards (orders today, revenue, conversion, abandoned carts 30d)
- **Interactions:** range change refetches all widgets; cards link to detail pages

### 3.2 Products — List
- **Layout:** filter bar (status, category, brand, stock level, search), toolbar (New Product, Import), offset-paginated table
- **Columns:** image, name, SKU, category, price (effective), stock, status badge, updated
- **Interactions:** row click → editor; inline status toggle; batch actions (activate, archive)

### 3.3 Products — Editor (tabs)
Tabbed editor: **General | Variants & Options | Images | Discounts | Photo Settings | Stock History**

**General tab**
- Fields: name, slug (auto-generate button), SKU, short description, description (rich text), category (tree select), brand (select), price, compare-at price, tags (chip input), attributes (compare-engine key-value rows), status (draft/active/archived)
- Validation: SKU uniqueness checked server-side with inline error; slug uniqueness

**Variants & Options tab**
- Options builder: rows of option name (Size, Color) with value chips; add/remove values; position arrows
- "Generate variants" button: builds the value matrix (2x3 → 6 variant rows)
- Variant table: SKU, price (inherit checkbox → product price), stock, image (media picker), active toggle, delete
- Unsaved option changes block variant generation until saved (values must exist to point at)

**Images tab**
- Upload dropzone → S3; gallery grid with drag-drop reorder (writes `sort_order`)
- Star control for primary image (one primary enforced); alt text inline edit; variant assignment select

**Discounts tab**
- List of scheduled discounts (type, value, window, active)
- Create form: type toggle (percent/fixed), value slider/input (percent capped at 100), start/end datetime pickers, active switch
- Multiple discounts allowed; tooltip on precedence rule (nearest active wins)

**Photo Settings tab (per-product overrides)**
- Three-state controls (Inherit / Override) per setting: format (vertical slideshow / horizontal slides), ratio (1:1 / 4:3 / 3:4 / 16:9 / custom), layout (grid / carousel), gutter (px slider), width (% slider), blend mode (multiply / normal), show photos (toggle)
- "Reset all to global" button clears overrides; saved as `products.photo_settings` JSONB

**Stock History tab**
- Ledger table: timestamp, qty change (+/-), reason badge, order reference, balance after
- "Adjust stock" action: delta input + reason (admin_adjustment) + note → writes `stock_movements`, updates balance

### 3.4 Categories
- **Layout:** tree view (indent levels, expand/collapse) + detail editor panel
- **Editor fields:** name, slug, parent (tree select), description, image (media picker), active toggle, navbar/megamenu toggles (show in navbar, show in megamenu, show images), sort order, per-category settings (photo settings with inherit model)
- **Interactions:** drag to re-parent/reorder; delete prompts about products in the category

### 3.5 Brands
- **Layout:** card/table list with logo thumbnails
- **Editor fields:** name, slug, logo upload, description, active toggle, sort order
- **Interactions:** reorder arrows/drag

### 3.6 Navigation
- **Layout:** two panels: navbar builder (left) and megamenu config (right), live preview strip on top
- **Navbar builder:** list of categories with checkboxes + up/down ordering (persisted to `navigation_settings`); "Add to navbar" pulls from the category tree
- **Megamenu config:** enable toggle, columns count, show-images toggle (per megamenu level)
- **Interactions:** every change emits `cms.updated`; preview updates immediately from local state, storefront within cache TTL

### 3.7 CMS Sections
- **Layout:** left: section list per page (homepage default, page selector), right: section editor with live preview pane
- **Section list:** drag-drop reorder; visibility toggle; add-section button (type chooser: hero, banner, featured products, category showcase, brand strip, blog teaser, testimonial)
- **Editor:** type-specific content form (e.g. hero: image, title, subtitle, CTAs (0-3, each `{text, link, bg, textColor, borderColor, borderWidth, borderRadius}`, Zod `ctas[]` max 3) — repeater with drag reorder per CTA, Add CTA disabled at 3, duplicate/delete per CTA; banner: same `ctas[0..3]`; alignment) + per-section settings (inherit model: ratio, blend mode, gutter, show photos, width)
- **Featured products picker:** product search + multi-select with order
- **Interactions:** live preview renders the section from local state using the storefront component (hero preview renders `ctas` row per slide); save validates `ctas.length <= 3` via `shared/src/schemas/cta.schema.ts` and shows inline Zod errors per CTA field; save emits `cms.updated`

### 3.8 Theme Settings (Global)
- **Layout:** grouped form: Colors, Border Radius, Image Ratios & Blend Mode, Typography [optional]
- **Colors:** color pickers with hex input — navbar background, navbar text, accent, buttons (bg/text), section backgrounds, footer
- **Border radius:** sliders for product cards, CMS section cards, buttons (0–24px)
- **Ratios & blend:** default image ratio select, default blend mode (multiply/normal)
- **Interactions:** live preview banner renders the current palette (CSS variables applied to a mock navbar/card); save bumps the settings version

### 3.9 Pages (static)
- **Layout:** page list + block editor
- **Editor:** slug, title, content blocks (heading/paragraph/image/quote/CTA — add, reorder, delete), SEO fields (title, description)
- **Interactions:** block add menu; drag-drop reorder; publish state toggle

### 3.10 Blogs
- **Layout:** post list (status filter, search) + post editor
- **Editor:** title, slug, cover upload, excerpt, category select, content blocks (same block system as Pages), status (draft/published), publish-now button, SEO fields
- **Interactions:** publishing emits `blog.updated`; draft posts hidden from storefront

### 3.11 Media Library
- **Layout:** responsive grid of thumbnails; filter chips (usage: product/section/blog; all), search by alt
- **Interactions:** multi-select → delete with in-use warning; alt-text inline edit; clicking opens detail with URL copy; used as the picker inside product images, section content, blog covers

### 3.12 Orders — List
- **Layout:** filter bar (status select, date range, customer search, order-number search), offset-paginated table
- **Columns:** order number, customer, grand total, status badge, payment status, created
- **Interactions:** row → detail; status filter chips

### 3.13 Orders — Detail
- **Layout (top-down):** header (order number, status actions), items table (snapshots), totals panel, addresses (shipping/billing), payment record, status history timeline, notes
- **Status actions:** dropdown of allowed transitions (state machine: pending → confirmed → processing → shipped → delivered; any → cancelled/failed; delivered → refunded via refund flow); optional note field; actor recorded
- **Refund:** amount input (full/partial), reason → creates payment refund record
- **Interactions:** status change emits `order.status.updated`; timeline refreshes

### 3.14 Discount Codes
- **Layout:** list (status filter) + create/edit form
- **Form fields:** code (uppercase normalize), type (percent/fixed), value, min order amount, max uses, active toggle
- **Expiry presets:** button group — 24 hours / 2 days / 5 days / 1 week / Custom date → sets `ends_at`; shows computed date/time
- **Interactions:** uses-count column on list; disabling rejects at checkout immediately

### 3.15 Customers
- **Layout:** searchable list (name/email) with order count + lifetime value
- **Detail:** profile info, addresses, orders table (link to order detail), abandoned-cart state, account status toggle
- **Interactions:** disable user blocks sign-in (confirmation dialog)

### 3.16 Abandoned Carts
- **Layout:** table (customer/session, item count, total, last activity, status: detected/reminded/converted, abandoned date)
- **Detail drawer:** items snapshot, cart event timeline
- **Interactions:** "Send reminder" button → publishes `cart.abandoned`, status → reminded

### 3.17 Analytics
- **Layout:** tabbed: Traffic | Funnel | Exits
- **Traffic:** daily page views + unique visitors chart, range picker
- **Funnel:** views → cart adds → checkouts → conversions with percentage drop-off per step
- **Exits:** bar lists: exits by page, exits by referrer
- **Interactions:** all tabs share the range picker

### 3.18 Import
- **Layout:** upload dropzone (CSV/JSON), source select (csv/json v1; connectors later), template download link, jobs table
- **Job row:** status badge (pending/processing/completed/partial/failed), totals (success/failed), created by/at
- **Job detail:** per-row error list (row number, field, message) with download of failed rows
- **Interactions:** upload → 202 → poll job until terminal; "Import again" re-runs a job

### 3.19 Users & Roles
- **Layout:** users table (name, email, roles, status) + roles manager
- **Role editor:** role name/slug, permission checkbox tree grouped by resource
- **Interactions:** assigning roles takes effect immediately; self-disable blocked

### 3.20 Email Log
- **Layout:** filtered table (status, recipient, template, sent at)
- **Detail:** expand for error detail on failed sends
- **Template editor [optional]:** key, subject, body with `{{variable}}` token hints

### 4.6 Hero / Banner CTAs (content — not settings, no inheritance)

CTAs are **content** arrays in `cms_sections.content` (see `3.Database-Schema.md` §4.1 and `pages/home.md` §3). ## 5. Override Model — Formalized

### 5.1 Precedence
```
Effective value = productOverride ?? sectionOverride ?? globalValue ?? builtinDefault
```
- **Product** (`products.photo_settings` JSONB) beats **Section** (section `settings`) beats **Global** (`cms_settings.theme`) beats **builtin default** (registry §4 defaults)
- Categories apply their `settings` JSONB to their listing pages (acts as a section-level override for that page)

### 5.2 Merge Algorithm
- JSONB deep merge: explicit key present → wins; absent key → falls through to the next level. No sentinel values needed
- "Reset to global" in the admin = delete the key from the product/section JSONB (never writes `null`)
- Rendering: the storefront resolves settings at render time into a single resolved object; a cache key includes the settings version to invalidate cleanly

### 5.3 Three-State Control (admin UX)
Each override-capable setting renders as a segmented control: **Inherit | Override**. Choosing Override reveals the value input. Choosing Inherit removes the key. A per-screen "Reset all to global" bulk action.

### 5.4 Example — product with override
```json
// products.photo_settings (product A)
{ "format": "horizontal_slides", "ratio": "4:3", "blendMode": "multiply" }
// effective on PDP for product A:
{ "format": "horizontal_slides", "ratio": "4:3", "layout": "carousel",   // from global
  "gutter": 8, "widthPercent": 100, "blendMode": "multiply", "showPhotos": true }
```

## 6. Settings Pipeline

```
Admin saves (PUT /cms/settings/global, PUT /sections/:key, PUT /navigation)
   → cms-svc writes Mongo document (bumps `version` counter)
   → publishes `cms.updated` {sectionKey, version}
   → consumers (storefront, search-svc):
       delete Redis keys cms:settings:global, cms:section:{key}
       → next SSR render: Redis miss → Mongo read → cache with TTL
```

### 6.1 Cache behavior
| Key | TTL | Written by | Invalidated by |
|---|---|---|---|
| `cms:settings:global` | 1 min | storefront/cms reads | `cms.updated` (settings) |
| `cms:section:{key}` | 5 min | storefront | `cms.updated` (section) |
| `cms:nav` | 5 min | storefront | `cms.updated` (navigation) |
| `search:suggest:{q}` | 10 min | search-svc | TTL only (acceptable staleness) |

### 6.2 Version counter
`cms_settings.version` increments on every global save. The storefront includes the version in its rendering cache key; on `cms.updated` it invalidates and refetches. ISR pages for the homepage revalidate on the same signal (stale-while-revalidate window 1 min).

### 6.3 Redis miss behavior
On cache miss the reader loads from Mongo, re-caches, and renders. Mongo M0 latency (~10–30ms) is acceptable for misses only; cache absorbs steady traffic.

### 6.4 CSS variable application
Global theme values are emitted by the storefront as CSS custom properties at the document root (`--color-navbar-bg`, `--radius-card`, `--photo-blend-mode`...), consumed by Tailwind config and inline styles. Per-section/product overrides become inline style props on the specific component — no global mutation.

## 7. Admin UX Patterns

### 7.1 Editor-with-Live-Preview
- Sections, theme, and navigation editors include a preview pane rendering the real storefront component against the local (unsaved) state
- Preview uses a query-scoped route on the storefront (`?preview=1&settingsVersion=<local>`) that reads overrides from a preview endpoint rather than Redis — no cache pollution from drafts
- Save publishes and invalidates caches (v1: save = publish)

### 7.2 Drag-Drop Ordering
- Section list, gallery images, navbar categories, blog/pages blocks: unified drag-drop component writing `sort_order`/order arrays on drop (optimistic reorder, revert on failure)

### 7.3 Media Picker
- A reusable modal (grid, search, usage filter) returned by any image field; selecting copies the S3 URL/key into the field; supports direct upload inline

### 7.4 Form Conventions
- Debounced autosave (2s) on editor tabs with a saved/reverted indicator and Ctrl+Z undo history per session
- Server validation errors inline per field; 409 conflicts (duplicate SKU, slug) shown as blocking banners
- All destructive actions require confirmation dialogs

### 7.5 Publish Flow
- v1: **save = publish** (immediate effect within cache TTL). Draft states exist per entity (products, blogs, pages) but settings do not
- Future: draft/live settings versioning noted in `0.Project-Overview.md` roadmap
