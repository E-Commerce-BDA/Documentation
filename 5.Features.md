# Part A — Storefront (Customer-Facing)

## A1. Homepage (`/`)

### A1.1 Hero Section
**Description:** The primary landing banner. Fully CMS-managed: per-slide image, headline, subtext, and **0-3 call-to-action buttons** (`content.slides[].ctas[]` max 3 via `shared/src/schemas/cta.schema.ts` Zod). Intrinsic product-card hover buttons (quick-add, wishlist) are excluded. Supports blend-mode (multiply/normal) and image-ratio settings.
**Key behaviors:**
- Rendered server-side from `cms_sections` (key: `home-hero`, `slides[]` array)
- Each slide holds image, headline, subtext, and `ctas[0..3]`; `0` = no CTA row, `1-3` = `flex flex-wrap gap-3` row; Admin Add CTA disabled at 3
- Each CTA links to any internal route (`/products`, `/products?category=...`); `link` validated as internal path
- Blend mode and ratio applied per CMS settings (global or section override)
**Acceptance criteria:**
- [ ] Admin edits hero text/image and the homepage reflects changes within the cache TTL (1 min) without a deploy
- [ ] `mix-blend-mode: multiply` and `normal` both render correctly over light and dark section backgrounds
- [ ] Ratio options (16:9, 4:3, 1:1, custom) maintain layout without overflow
- [ ] Each CTA (0-3 per slide) navigates to its configured route; `ctas: []` renders no CTA row; `ctas.length > 3` is rejected with `400 VALIDATION_FAILED` and inline Zod error; per-CTA styles (`bg/textColor/borderColor/borderWidth/borderRadius`) apply correctly

### A1.2 Banner Strip
**Description:** One or more promotional banners with image, text, and **0-3 CTAs** (`content.ctas[]` max 3 via Zod, same `Cta` shape as hero).
**Key behaviors:**
- Admin-managed set of banners, ordered
- Each banner can be hidden individually
- Each banner holds `ctas[0..3]`; `0` = no CTA row; Add CTA disabled at 3
**Acceptance criteria:**
- [ ] Banners render in configured order with correct links; each CTA (0-3) navigates
- [ ] Hidden banners disappear from the page but remain in admin
- [ ] `ctas.length > 3` rejected with `400 VALIDATION_FAILED`

### A1.3 Featured Products Carousel
**Description:** A carousel of products selected by the admin (by product id list or category).
**Key behaviors:**
- Layout configurable: grid vs carousel (CMS)
- Card visuals follow global/theme settings (border radius, image ratio)
- Clicking a product navigates to its PDP
**Acceptance criteria:**
- [ ] Admin selection order is preserved in the carousel
- [ ] Grid and carousel layouts both render correctly
- [ ] Unavailable (archived/inactive) products are hidden automatically

### A1.4 Category Showcase Section
**Description:** A section presenting selected categories with images and names.
**Key behaviors:**
- Admin selects categories and whether to show images
- Clicking a category card navigates to its listing page
**Acceptance criteria:**
- [ ] Selected categories render in order
- [ ] Toggling "show images" off renders text-only cards

### A1.5 Brand Logos Strip
**Description:** A horizontal strip of brand logos linking to brand listing pages.
**Key behaviors:**
- Admin toggles section visibility
- Logos sourced from `brands.logo_url`
**Acceptance criteria:**
- [ ] Active brands with logos appear; inactive/hidden brands do not
- [ ] Each logo links to the brand listing

### A1.6 Blog Teaser Section
**Description:** Shows the latest N published blog posts (admin-selectable count).
**Key behaviors:**
- Pulls from published blogs ordered by `published_at`
- Links to individual blog pages
**Acceptance criteria:**
- [ ] Only published posts appear
- [ ] Configured count renders; empty state shown when no posts exist

### A1.7 Testimonial Section [optional]
**Description:** CMS-managed testimonial cards (quote, name, avatar).
**Key behaviors:**
- Admin CRUD for testimonials
**Acceptance criteria:**
- [ ] Testimonials render from CMS data; hidden when empty

### A1.8 Dynamic Section System
**Description:** The homepage is assembled from ordered sections defined in the CMS; admin can add, reorder, activate, or remove sections without code changes.
**Key behaviors:**
- Section order from `sort_order` in `cms_sections`
- Unknown/disabled section types are skipped gracefully
- Section data cached in Redis, invalidated on `cms.updated`
**Acceptance criteria:**
- [ ] Admin reorder is reflected on the next page load (within cache TTL)
- [ ] Adding a new section of an existing type renders without deploy
- [ ] Removing all sections renders a minimal but functional homepage

## A4. Cart Page (`/cart`)

### A4.1 Cart Line Items
**Description:** Each item shows image, name, variant options (e.g. Size: S, Color: Red), unit price, qty stepper, line total.
**Acceptance criteria:**
- [ ] Variant options render from the junction-resolved combination
- [ ] Line totals equal qty x unit price (snapshot price)

### A4.2 Quantity Update
**Description:** Stepper updates quantity, debounced.
**Acceptance criteria:**
- [ ] Quantity updates persist and totals recalculate
- [ ] Quantity cannot exceed available stock
- [ ] P99 for qty update is under 100ms at 200 line items

### A4.3 Single & Batch Remove
**Description:** Remove one item, or select multiple and remove together.
**Key behaviors:**
- Batch remove is a single API call (`DELETE /cart/items` with `ids[]`)
- Optimistic UI removes rows instantly
- Emits one `cart.updated` per mutation (fire-and-forget)
**Acceptance criteria:**
- [ ] Single and batch removal both work
- [ ] P99 for removal is under 100ms with a 200-item cart (see Part C3)
- [ ] Removing all items renders the empty state

### A4.4 Totals Panel
**Description:** Subtotal, discount (coupon), shipping, tax, grand total.
**Acceptance criteria:**
- [ ] Totals recalculate on every mutation
- [ ] Discount line appears only when a valid coupon is applied

### A4.5 Coupon Apply/Remove
**Description:** Apply a discount code with inline validation feedback.
**Key behaviors:**
- Validates against `discount_codes` (active, date range, usage limit, min order)
- Errors: invalid, expired, already used, below minimum
**Acceptance criteria:**
- [ ] Valid coupon updates totals correctly (percent and fixed)
- [ ] Expired/used/insufficient-order coupons show specific error messages
- [ ] Removing the coupon restores pre-discount totals

### A4.6 Guest Cart & Merge
**Description:** Guest carts persist via session; on sign-in the guest cart merges into the user's cart.
**Acceptance criteria:**
- [ ] Guest cart survives page reloads
- [ ] On login, same-product lines merge quantities; different products append
- [ ] No duplicate line items after merge

### A4.7 Empty Cart State
**Acceptance criteria:**
- [ ] Empty cart shows a friendly message and continue-shopping link

### A4.8 Mini-Cart Drawer
**Description:** A slide-in drawer showing cart summary from anywhere in the store.
**Key behaviors:**
- Shows line items, totals, and a checkout button
- Synchronized with cart state (Zustand store)
- Accessible: close on overlay click / Escape key
**Acceptance criteria:**
- [ ] Drawer opens from navbar cart icon on every page
- [ ] Adding/removing items updates the drawer without full page reload
- [ ] Checkout button navigates to `/checkout`

## A10. Search

### A10.1 Typeahead Suggest (Navbar Search Bar)
**Description:** Instant suggestions combining categories, products, and blogs.
**Key behaviors:**
- Client: debounce 300ms, minimum 2 characters, abort stale requests, in-memory cache with stale-while-revalidate
- Server: `GET /search/suggest` via search-svc (prefix tsvector match, Redis-cached 10 min)
- Response grouped: categories, products, blogs (5+5+5)
**Acceptance criteria:**
- [ ] Typing 1 character triggers no request; 2+ characters after 300ms pause trigger one
- [ ] Aborted responses never overwrite newer ones
- [ ] Re-typing a previously cached query shows results instantly (no network)
- [ ] Clicking a result navigates to the right page; Enter goes to full search

### A10.2 Search Results Page
**Description:** Full ranked results with filters (category, price), sort, cursor pagination, total hits.
**Acceptance criteria:**
- [ ] Results ranked by relevance (ts_rank) then popularity
- [ ] Filters and pagination behave like the listing page (A2)
- [ ] No results state with suggestions for other queries

## B2. Products

### B2.1 Product List
**Description:** Searchable, filterable (status, category, brand, stock level), paginated list.
**Acceptance criteria:**
- [ ] Filters combine; pagination uses admin offset mode

### B2.2 Product Create/Edit
**Description:** Full editor: name, slug (auto), SKU, description, price, compare-at price, category, brand, tags, attributes, status.

- [ ] Stock balance updates and ledger shows the movement with reason

- [ ] Stock history view shows full ledger timeline

### B2.6 Scheduled Discounts
**Description:** Create percent/fixed discounts with start/end dates and active toggle.
**Acceptance criteria:**
- [ ] Discount applies on storefront only within its window
- [ ] Multiple discounts on one product: nearest active wins (documented rule)

### B2.7 Per-Product Photo Settings
**Description:** Override global photo settings per product: format, ratio, layout, gutter, width, blend mode, show/hide photos.
**Acceptance criteria:**

**Acceptance criteria:**

# Part C — Cross-Cutting Requirements

## C1. Auth & RBAC Enforcement

| Area | Requirement |
|---|---|
| Storefront APIs | Bearer JWT; customer role for account/checkout/wishlist; guest access via session for cart |
| Admin APIs | Admin role enforced by RolesGuard on every route group (B2–B18) |
| Admin app routes | Route-level guard matching API permissions |
| Service-to-service | `x-service-key` on all internal calls; not exposed publicly |
| Rate limits | login/refresh 10/s, checkout 5/s, events 30/s (Nginx) |

## C2. Performance Targets

| Target | Threshold | Verification |
|---|---|---|
| Cart mutation (add/update/remove/batch) | P99 < 100ms with a 200-line-item cart | k6/load script in CI against seeded cart (see `4.API-Design.md` A4) |
| PDP render | P99 < 300ms server response (uncached) | Seed product with 2 options x 20 values (400 variants) |
| Typeahead suggest | P99 < 150ms | Debounce + Redis cache absorbing repeat traffic |
| Search page | P99 < 250ms | tsvector GIN + cursor pagination |

## C3. SEO Requirements

| Page type | Strategy |
|---|---|
| Homepage | SSR + ISR (revalidate on `cms.updated` via cache purge) |
| Product listing | SSR + ISR (filters client-side or pre-rendered top filters) |
| PDP | SSR + ISR; unique meta, OG, canonical, Product JSON-LD |
| Blog list/detail | SSR + ISR; Article JSON-LD |
| Cart/Checkout/Account | Client-rendered (private data, never cached) |
| All pages | Sitemap.xml + robots.txt generated from catalog + blogs |

## C4. Analytics Events

| Event | Trigger points |
|---|---|
| `page.viewed` (pageview) | Every storefront route via sendBeacon → `/api/track` → analytics-svc |
| `page.viewed` (heartbeat, exited) | `beforeunload`/`visibilitychange` — exit tracking input |
| `cart.updated` | All cart mutations |
| `order.created` | Successful checkout |
| `user.registered` | Signup |
| Funnel inputs | Views → cart adds → checkouts → conversions (derived in analytics-svc) |

## C5. Privacy & Data Handling

- Analytics use anonymous session IDs unless logged in
- Guest carts scoped to session cookie; PII only stored for authenticated users
- Email addresses never logged in raw analytics payloads
- Delete account request purges PII from auth + analytics user references [optional]
