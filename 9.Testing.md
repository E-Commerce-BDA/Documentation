## 1. Scope + Pyramid

Each of the 12 repos owns its suite and runs it in CI (`lint → test → build → push ghcr.io/<org>/<repo>:<sha>`). No cross-repo test imports — shared fixtures/types come only from pinned `@ecom/contracts`.

```
Unit (Jest/Vitest, fast, no DB)
  → API e2e (supertest + seeded DB)
    → Contract (@ecom/contracts semver + OpenAPI diff)
      → Frontend (RTL + Playwright)
        → Load (k6, nightly + pre-release)
          → Resilience/chaos (outbox replay, DLQ, Redis-down, restart)
```

**Tooling (locked):** backend unit + API e2e = `Vitest 4.x` + `supertest`; frontend unit = `Vitest` + React Testing Library; browser e2e = `Playwright`; load = `k6`; lint = `typescript-eslint` + Prettier + Husky/lint-staged. No coverage gate in v1 (record coverage, enforce later); a failing suite blocks image push.

## 2. SLO Table (Binding)

Latency is a distribution. p50 = typical user, p90 = busy user, **p99 = worst realistic user (binding SLO)**. Averages are not used — they hide the 1% that churns.

| Flow | p50 target | p90 target | **p99 SLO** | How verified |
|---|---|---|---|---|
| Cart mutation (add/update/remove/batch) @ 200 line items | <40ms | <70ms | **<100ms** | k6 seeded 200-item cart; PK delete + 1 indexed join + fire-and-forget `cart.updated` (see `3.Database-Schema.md §6.1`) |
| Typeahead suggest | <60ms | <100ms | **<150ms** | Debounce 300ms + Redis `search:suggest:{q}` 10min; abort stale |
| Search page | <120ms | <180ms | **<250ms** | tsvector GIN + cursor pagination |
| PDP server response (uncached, 400 variants) | <150ms | <220ms | **<300ms** | Seed 2 options × 20 values; slug index + 5 bounded queries |

Measured in prod via ALB `TargetResponseTime` p50/p90/p99 + service pino `durationMs` histograms (see `10.Observability.md §3`). **Alarm on p99; watch p50 for regressions.** CI k6 asserts p99; p50/p90 recorded for trend.

## 3. Per-Repo Suite Checklist

### 3.1 auth-svc
- Register → login → refresh rotation → logout revokes refresh; weak password rejected; duplicate email → `409`.
- Login with bad credentials → generic `401` (no user enumeration); login/refresh rate limit → `429`.
- Disabled user blocked at login; `PATCH /me/password` revokes existing refresh tokens.
- RBAC: `customer` denied 👑 routes (`403`); permission change effective on next call.

### 3.2 catalog-svc
- Product CRUD: duplicate SKU → `409 DUPLICATE_SKU`; slug auto-unique; archived products hidden from storefront reads.
- Variants matrix: 2 options × 3 values → exactly 6 variants; deleting an option value warns/blocks.
- Discounts: future/expired/overlapping windows — only active window applies; nearest-active-wins rule; percent >100 rejected.
- Images: exactly one primary enforced; reorder writes `sort_order`.

### 3.3 cart-svc
- Guest cart persists by session; one active cart per session under concurrent create; login applies `guestMergeStrategy`.
- `merge` (default): same `(product_id, variant_id)` lines sum quantities; different lines append; no duplicate lines. `guest_wins`: guest cart becomes the active user cart; old user cart `converted`. `user_wins`: user cart kept; guest `converted`; if user is empty, guest adopted.
- The only non-empty cart is never lost; both-empty and no-guest-cart cases return cleanly; a merge retry is a no-op.
- Add/update/remove/clear: totals match rows; foreign item → `404`; batch `DELETE /cart/items {ids[]}` = 1 round trip; remove-all → empty state.
- Idempotency: same key returns the stored response; different body → `409 IDEMPOTENCY_CONFLICT`; Redis down → `503` for keyed mutations.
- Settings: admin GET/PATCH; customer 403; anonymous 401; unknown key/invalid value 400; reset deletes the override; stale version 409; audit row written; `no-store`; no public settings route; spoofed `x-user-id`/`x-roles` rejected.
- Wishlist: customer 200; admin-only/no-role 403; guest 401; empty list on a new user with no wishlist row; add; duplicate 201 same item and one row; product-level uniqueness across variants; foreign/missing delete 404; remove 204; no `cart.updated`; no snapshot; `updated_at` touched.
- Wishlist auth: cart-svc re-verifies the JWT and checks `customer`; spoofed `x-user-id`/`x-roles` without a valid customer token → 401/403.
- Schema: six tables, guest-session partial unique index, settings/audit triggers; re-running `002` preserves an existing settings document.
- Every cart mutation emits exactly one `cart.updated` fire-and-forget (never awaited in response path); merge emits one for the resulting cart.

### 3.4 order-svc
- Idempotency: same `x-idempotency-key` twice → exactly 1 order, replay returns original; key reused with different body → `409 IDEMPOTENCY_CONFLICT`.
- `STOCK_INSUFFICIENT` names offending item; cart intact on failure; `COUPON_EXPIRED` / `COUPON_USED` / below-minimum each return distinct codes.
- Outbox: order row + outbox row in same TX; relay publishes `order.created`; stock-fail → `failed` + `order.status.updated` compensation.

### 3.5 cms-svc
- Sections CRUD + reorder + activate; `ctas.length > 3` → `400 VALIDATION_FAILED` with inline field path; `ctas: []` renders no row.
- Legacy flat `ctaText/ctaLink` auto-migrates to `ctas[0]`; unknown section types skipped gracefully.
- Global save bumps `version`; emits `cms.updated`; storefront reflects within TTL.

### 3.6 analytics-svc
- `page.viewed` pageview + heartbeat (`exited: true`) aggregate to exits-by-page/referrer; funnel views → adds → checkouts → conversions.
- Abandonment detector: idle >24h → `cart.abandoned` once per cart; re-send flips `detected → reminded`.

### 3.7 import-svc
- 1000-row CSV/JSON → `completed/partial/failed` report; per-row `{row, field, message}`; duplicate SKUs reported without aborting batch.
- Template download documents all columns; re-run updates (no duplicates via `(source, external_id)`).

### 3.8 notify-svc
- Consumes `order.created` / `cart.abandoned` / `user.registered` / `order.status.updated`; failed sends recorded with error; `POST /admin/test-email` → `202`.
- Template `{{variable}}` substitution; missing variable fails loudly in test, never silently in prod.

### 3.9 search-svc
- `/suggest`: 1 char = no request (client); 2+ chars after 300ms = 1 request; aborted responses never overwrite; cached re-type = no network.
- Blog drafts never indexed; inactive products filtered; ranking = `ts_rank` then popularity.
- Indexing idempotency: replaying Kafka events or batch ingestion does not duplicate rows; unique `(document_type, id)`.
- Stale guard: incoming updates with older `source_updated_at` are rejected/skipped without mutating rows.
- Full search: cursor is cryptographically bound to query and filters; prevents pagination drift across altered queries.
- Degraded mode resilience: Postgres down = 503; Redis down = 200 ready (search serves from DB); Kafka down = 200 ready (search serves existing index).
- Internal batch ingest: rejects without valid `x-service-key`; rejects payloads > 500 documents or > 1MB.

### 3.10 storefront-ui / admin-app
- Base components: all variants × states (default/hover/focus-visible/disabled/loading/invalid) + keyboard + focus ring; sale badge uses ink text (never white on `#FF6B4A`).
- Flows: optimistic cart add + revert on stock error; checkout double-click = 1 order; unauthenticated `/account`/`/checkout` → `/signin` with return path; `?preview=1` never pollutes Redis.
- Guest wishlist: heart prompts sign-in; pending product id survives `?next=` or a short-lived cookie (never `localStorage`); post-login POST; duplicate no-op; heart state is product-based.

## 4. Local Harness: Bring-Up and Test Commands

Every messaging test runs against the one local stack in `ecom-infra/docker-compose.yml` (Postgres, Redis, Mongo `rs0`, Kafka, LocalStack SQS/IAM, Mailpit). Nothing in this section needs AWS credentials.

### 4.1 Bring the stack up

```powershell
cd E:\E-Commerce\ecom-infra
pnpm install --ignore-workspace   # pins @ecom/contracts 1.8.0 by tarball
pnpm up                           # docker compose up -d
pnpm verify                       # 31 checks — the gate
```

`pnpm up` is complete when all six containers report healthy (every service has a healthcheck, and Mongo's is `isWritablePrimary`, not "the process is alive"). `pnpm verify` asserts container health, that `mongo-rs-init` exited 0, the Postgres schema/table floors, a real Mongo transaction, three SQS queues plus their DLQs with `maxReceiveCount 5`, and one SMTP message stored by Mailpit. A full reset is `docker compose down -v` followed by `pnpm up` — the Postgres databases are then empty and each service's `db/` schema files must be re-applied.

### 4.2 Topic creation

```powershell
pnpm topics:provision   # 11 topics + 11 DLQs from EVENT_TOPICS; idempotent
pnpm topics:smoke       # 28 checks
```

The provisioner is the only writer: auto-create is off in the broker, so a topic that is not in `EVENT_TOPICS` cannot exist. A second `topics:provision` run prints `nothing to do: 22 topics already match the registry`. The smoke test reads back partitions and `retention.ms` per topic, proves keyed partitioning across all partitions on a throwaway topic, proves producing to an undeclared topic is rejected (`UNKNOWN_TOPIC_OR_PARTITION`), and proves no strays exist.

### 4.3 Queue creation

Locally there is no manual step: `localstack/init/ready.d/10-sqs-queues.sh` runs on the ready hook and creates `notify-send-email`, `import-process-row` and `media-resize-image` with their `-dlq` twins. To rerun it, recreate only LocalStack:

```powershell
docker compose rm -sf localstack; docker compose up -d localstack
```

In AWS the same objects come from `ecom-infra/aws/`. Exercise the configuration against LocalStack with a throwaway prefix so a test apply cannot touch the dev queues:

```powershell
docker run --rm -v "${PWD}/aws:/tf" -w /tf hashicorp/terraform:1.9 validate
docker run --rm -v "${PWD}/aws:/tf" -w /tf -e AWS_ACCESS_KEY_ID=test -e AWS_SECRET_ACCESS_KEY=test `
  hashicorp/terraform:1.9 apply -auto-approve -var endpoint=http://host.docker.internal:4566 -var queue_prefix=tfcheck-
# ...assert, then:
docker run --rm -v "${PWD}/aws:/tf" -w /tf -e AWS_ACCESS_KEY_ID=test -e AWS_SECRET_ACCESS_KEY=test `
  hashicorp/terraform:1.9 destroy -auto-approve -var endpoint=http://host.docker.internal:4566 -var queue_prefix=tfcheck-
```

## 5. Event Log + Task Queue Matrix (Kafka + SQS side-by-side)

Events ride Kafka; tasks ride SQS. Each workload is tested on its own transport (`1.Architecture.md §6.6`).

### 5.1 Concern matrix

| Concern | Kafka event assertion | SQS task assertion |
|---|---|---|
| Producer outbox | Request handler writes the domain row + the outbox row in one Postgres transaction; the relay is the only publisher, marks `published` only after broker ack, and a killed relay replays on boot without duplicating | The task producer writes the enqueue inside the same handler that recorded the state change; a re-enqueue after a crash carries the same `idempotencyKey` |
| Consumer dedupe | Redelivery of the same envelope is dropped by `processed_events` (insert-first, then side effect); the second attempt is a no-op, not a duplicate write | Standard queues may deliver twice: the worker keys on `idempotencyKey` (`notify.email_logs` for email) and drops the second delivery |
| Ordering | Per-key order (`cart.updated` by `userId\|sessionId`, `order.created` by `orderId`) holds across partitions | Standard queues (order irrelevant for v1 tasks); FIFO only if a per-user ordered task is added later |
| Failure / DLQ | 5× backoff (1/2/4/8/16s) → `<topic>.dlq`; malformed JSON and invalid known payloads go to the DLQ on the **first** attempt; the group never stalls | Redrive `maxReceiveCount 5` → `<queue>-dlq`; the worker never stalls and DLQ depth is alarmed |
| Replay | Re-consume `product.imported` after a search bug (3–30d retention) — the documented recovery path | **N/A** — tasks retry via redrive/visibility-timeout, they are not replayable; a lost task is re-driven by the producer |
| Fan-out | 1 topic → N consumer groups | 1 queue per job type: `notify-send-email`, `import-process-row`, `media-resize-image` |
| Cost hygiene | N/A | Long-poll 20s + batch 10 ($0.40/M Standard / $0.50/M FIFO, 1M free, 64KB chunks) |

### 5.2 P0 regression cases

These are the cases that must be green before a release; each one has burned a real bug or is named in an acceptance criterion.

| # | Case | Transport | Test location |
|---|---|---|---|
| P0-1 | Order commit writes `orders` + `order_outbox` in one transaction; a stock failure rolls both back and emits no `order.created` | Kafka (outbox) | `order-svc/test/checkout.e2e-spec.ts` |
| P0-2 | The same `order.created` redelivered claims the reservation once and records one order id | Kafka (dedupe) | `catalog-svc/test/order-created.e2e-spec.ts` |
| P0-3 | An unparseable payload lands in `<topic>.dlq` on the first attempt with `reason: invalid-json` and the offset still commits | Kafka (DLQ) | `search-svc/test/kafka-event-consumer.spec.ts` |
| P0-4 | Replaying `product.imported` does not duplicate search rows (unique `(document_type, id)`) | Kafka (replay) | `search-svc/test/indexer.e2e-spec.ts` |
| P0-5 | A poisoned task lands in `notify-send-email-dlq` after exactly 5 receives, and a redelivered task with the same `idempotencyKey` never sends twice | SQS (DLQ + dedupe) | `notify-svc` (repo not built yet — see §3.8) |
| P0-6 | `sendEmailJobSchema` rejects a payload that embeds an email address — PII never enters a queue either | Contracts | `ecom-contracts/test/jobs.spec.ts` |
| P0-7 | `TASK_QUEUE_NAMES` and `TASK_DLQ_NAMES` match the names the init hook and Terraform create (no dots, `-dlq` twin) | Contracts + infra | `ecom-contracts/test/jobs.spec.ts`, `ecom-infra` `pnpm verify` |
| P0-8 | The 22 topics match `EVENT_TOPICS` (partitions + retention) and producing to an undeclared topic is rejected | Kafka (auto-create) | `ecom-infra` `pnpm topics:smoke` |
| P0-9 | Mongo runs a transaction that aborts cleanly against the replica set (the `cms_outbox` requirement) | Mongo | `ecom-infra/scripts/verify-stack.mjs`, `cms-svc/test/mongo.e2e-spec.ts` |
| P0-10 | A guest cart merge produces exactly one `cart.updated` for the resulting cart | Kafka (producer) | `cart-svc/test/cart-merge.e2e-spec.ts` |

## 7. Load + Chaos

- **k6 (CI nightly + pre-release, all assert p99):** `cart-mutation.js` (seeded 200-item cart), `pdp-400-variants.js`, `suggest-burst.js` (cold vs Redis-hit), `checkout-ratelimit.js` (5/s → `429`). Thresholds live beside scripts (e.g. `p(99)<100` for cart).
- **Chaos (learning-scale, manual + CI job):** event consumer kill mid-batch → redelivery deduped; poison message → Kafka DLQ, group never stalls; task worker kill → redrive DLQ; poison task → task DLQ; Redis down → DB fallback; EC2 restart → outbox replay (Kafka log replays, SQS tasks survive 14d); SQS throttle → backoff + queue-age alarm; stock reservation fail → order `failed` + compensation event.

## 8. Test Data + Environments

- **Fixtures (checked in):** users (customer/admin/disabled), addresses, 200-item cart seed, 400-variant product seed, 1000-row import CSV (valid + dup-SKU + bad-price rows), CMS hero with 0/3/4 CTAs, discount windows (active/expired/future). No real PII; analytics tests use synthetic session IDs.
- **Environments:** one compose stack (`ecom-infra/docker-compose.yml`) provides Kafka, Redis, Postgres and Mongo `rs0`; SQS task queues come from LocalStack in the same stack (or real AWS with the same Terraform); same fixtures everywhere.

## 9. Post-Deploy Verification

- **Smoke (every deploy, automatic):** `/health` + `/health/ready` per service → Compose/ALB checks; deploy one service at a time (`ecom-infra/VERSIONS.env` pins immutable tags; rollback = revert one line).
- **Synthetic probes (5 min):** register → add → checkout → suggest → CMS publish → storefront reflect; alert on p99 breach or 5xx.
- **Alarms (see `10.Observability.md §4`):** 5xx rate, checkout/suggest p99, queue age / consumer lag, DLQ depth, RDS CPU/storage, credits 50/25/10% + 15/7/2-day expiry.
- **Debug path:** `x-request-id` from Nginx → filter across services in CloudWatch Logs; replay the Kafka log after event bugs; task failures via task DLQ + job report.
