## 1. Scope

## 2. Logs

- pino JSON to stdout → Docker logs → CloudWatch Logs (one group per service).
- Every line carries `requestId` (`x-request-id` from Nginx), `service`, `level`, `durationMs` where relevant.
- Debug path: filter `requestId=<id>` across groups to trace checkout end-to-end.

## 3. Health + Metrics

- `GET /health` (liveness) + `/health/ready` (deps: DB/Redis/bus) per service → Compose `depends_on` + ALB checks. Shapes, status codes, and the envelope/rate-limit exemptions: `4.API-Design.md §1.9`.
- RED per service: rate (req/s), errors (5xx), duration (p50/p90/**p99** — SLOs in `9.Testing.md §2`).
- Transport: SQS task queues via `ApproximateAgeOfOldestMessage` / `ApproximateNumberOfMessagesVisible`, DLQ depth (per task queue).
- **Kafka consumer lag is now measured, not inferred** (`srch-002`, `ca-009`, `cat-008`). The
  counters and the sampler are `@ecom/messaging`'s, so all three consumers keep the same nine
  (`accepted`, `skipped`, `committed`, `duplicate`, `ignored`, `invalid`, `dlq`, `commit`,
  `stalled`) and read the group's position the same way: `lag` per topic, `totalLag`, `lastCommit`
  (`{ topic, partition, offset }`), `sampledAt`. Two of the three expose them —
  `GET /api/v1/catalog/internal/consumer-stats` and `GET /api/v1/search/internal/consumer-stats`,
  `x-service-key`, `Cache-Control: no-store`. **cart-svc has the counters but no route** (named
  debt): its group is observable only from the CLI until an endpoint is added.
  The sampler is `KafkaLagSampler`, an admin client outside the Nest strategy on an unref'd 15 s
  timer, so it never holds the process open; a `-1` committed offset counts as **never committed**,
  not as lag, and the payload is `null`/empty until the first sample rather than a fake zero. Lag
  without `lastCommit` cannot distinguish "behind" from "stopped", which is the exact question this
  endpoint exists to answer. `kafka-consumer-groups.sh --describe` remains the external cross-check,
  and the group id must be exactly the service name — a `-server` twin means two groups are splitting
  the partitions and neither sees every record.
- Producers: **all five producer services now own outbox rows** — `auth.outbox`,
  `cart.outbox`, `catalog.outbox`, `order.outbox` and the Mongo `cms_outbox` — so producer
  health is finally observable per service instead of per service-that-bothered. The signals
  are `<schema>.outbox` depth, `status = 'failed'` count, oldest `pending` age, and whether the
  relay currently holds its lock (Postgres: `pg_try_advisory_lock`; Mongo: the
  `cms_outbox_locks` lease document's `locked_until`). They are **not emitted yet**: no service
  has a metrics endpoint for them, so today each one is a single SQL/Mongo query per schema.
  That is debt, not coverage — `tst-001` and the observability tasks are where it gets paid.
  One consequence of the Mongo store: the `failed` count is per *collection*, and a relay that
  crashed holding the lease shows up as a `locked_until` in the future, not as a missing lock.
- Two newer signals ride the same status: `cart-svc` fails add-to-cart closed with
  `503 CATALOG_UNAVAILABLE` (`ca-010`), and the storefront degrades to a stale memory entry or the
  demo nav when cms-svc is unreachable (`sf-050`). **Neither is counted anywhere yet** — the cart
  answers a 503 that RED sees as an error, but it cannot say how many of its 5xx are the catalog
  versus itself, and the storefront answers `200` while logging `fallback: true` / `stale: true`
  in a place no dashboard reads. Both are debt: `CATALOG_UNAVAILABLE` needs a counter on the cart
  RED endpoint, and the storefront needs to emit its own.
- The CMS→UI invalidation arrow has no observability at all. `POST /api/revalidate` returns
  `revalidated[]` to its caller (cms-svc, from `cms-007`), and nothing records whether the call
  happened, what it purged, or that it 401'd because a secret rotated — a silent 401 is a cache
  that never purges, which is the failure mode that looks like "the CMS is broken" and isn't.
  Log the outcome on both ends when `cms-007` lands; a purge that nobody can see is a purge nobody
  can trust.

## 4. Alarms (CloudWatch)

| Alarm | Threshold (v1) |
|---|---|
| 5xx rate per service | >1% over 5 min |
| Checkout p99 / suggest p99 | breach of `9.Testing.md §2` SLOs |
| Queue age (SQS tasks) / consumer lag (Kafka) | age >5 min / lag growing 10 min |
| DLQ depth (Kafka `.dlq` + SQS task DLQs) | >0 for 5 min |
| Outbox `failed` rows (`auth.outbox`, `cart.outbox`, `catalog.outbox`, `order.outbox`, `cms_outbox`) | >0 for 5 min — a parked row is a lost event until someone republishes it. The threshold is now five tables instead of two, and the three it gained are the ones that had no durable producer before, so this alarm is the first place a broken catalog/order/cms publish shows up |
| Oldest `pending` outbox row / relay lock held | age >5 min / lock held longer than one batch should take. Applies to both stores: a Postgres advisory lock and a Mongo `cms_outbox_locks` lease expire differently, so the "held too long" check has to be store-specific |
| RDS CPU / storage | >80% / <20% free |
| Credits | 50/25/10% remaining + 15/7/2-day expiry (AWS sends expiry mails) |

All alarms route to the alerter (§5). Dashboards: one CloudWatch dashboard (requests, p99, errors, queue age, DLQ, RDS) — screenshots deferred.

## 5. Alerting — Crash/Error to Phone (BASIC — detail later)

> TODO: full design deferred (watcher location, message templates, Terraform, BotFather/SNS setup, cost table, on-call runbook, self-test). Basic intent only below.

- **Purpose:** notify phone on DOWN / ERROR-burst / BACKLOG even when the app itself is down — watcher runs outside the 9 services.
- **Channels:** Telegram bot (all severities, free, instant) + SNS SMS (DOWN only, cost control). Email explicitly out of scope.
- **Signals:** `/health` 3 consecutive fails = DOWN; error-log burst (>5 errors/5min) = DEGRADED; DLQ depth >0 or queue age >5min = BACKLOG.
- **Dedupe:** one alert per incident + "recovered" message; 15-min cooldown; severity prefix (`🔴 DOWN` / `🟠 DEGRADED` / `🟡 BACKLOG`).
- **Next (deferred):** `ecom-infra/watcher/` implementation, secrets handling (never in git), runbook steps, staging self-test (kill a service → assert Telegram + SMS).
