# Comment ratchet (ADR-comments-ratchet)

`count_comments.py` is a standalone pre-merge check. It records one reviewable
comment count per code repo and fails only when a repo goes **above** its
baseline. Removing comments can never fail the gate.

No CI hook, workflow or lint rule is configured here — this repo documents the
gate and supplies the command; a CI job may call the same command later without
changing the script. A hard lint rule was rejected by the ADR: it would block
every merge while the inventory was still being worked.

## What is counted

- **Unit:** a comment *line* in `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`,
  `.py`, `.sh`, `.ps1`, `.yml`, `.yaml` and `.sql` files. A string-aware scanner
  keeps `"https://..."` out of the count. Regex literals and nested `${}`
  template expressions are the documented simplifications.
- **Generated files are skipped:** `node_modules/`, `dist/`, `build/`, `out/`,
  `coverage/`, `.next/`, `.turbo/`, `.git/`, `.cache/`, `__pycache__/`, virtual
  envs, `vendor/`, `generated/`, lockfiles, `*.min.js`, `*.d.ts`, `*.map`,
  `*.snap`, and any file marked `@generated`, `auto-generated`, `generated by`
  or `do not edit`.
- **Sanctioned reason-required constructs are skipped:** comments containing
  `reason:`/`why:`, `ADR-<id>:` pointers, lint/compiler directives (`eslint`,
  `@ts-`, `prettier`, `vite-`, `@ts-expect-error`, `@deprecated`, …), and the
  justifications AGENTS.md §5 requires for `!important`, `console.*`,
  `localStorage` and `??`. They are not removable by choice.
- Documentation and `state-for-agents` are not code repos and are not counted;
  the ratchet does not count its own source.

## Commands

Run from anywhere — the polyrepo root is derived from the script location:

```powershell
python E:\E-Commerce\Documentation\scripts\comment-ratchet\count_comments.py
```

- Exit `0`: every repo is at or below its baseline.
- Exit `1`: at least one repo rose above its baseline; the line names the repo,
  its baseline and its current count.
- Exit `2`: configuration error (missing/unreadable baseline, unknown `--repo`,
  no repos found).

Useful flags:

- `--json` — machine-readable `{"counts": ..., "violations": ...}`.
- `--repo <name>` — restrict the check (repeatable); names match `REPOS` in the
  script.
- `--root <path>` — check another checkout.
- `--baseline <path>` — use another baseline file.
- `--update-baseline` — **write the new baseline**. Do this only after reviewing
  each added comment against ADR-comments, and say why in the commit body. A
  baseline bump is an explicit approval, not a way to silence the gate.

## Test

```powershell
cd E:\E-Commerce\Documentation\scripts\comment-ratchet
python -m unittest -v test_count_comments.py
```

The test asserts that adding one unapproved comment exits `1`, that removing
comments exits `0`, and that generated and sanctioned comments are excluded.
