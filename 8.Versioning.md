## 1. Repository and package

| Item | Value |
|---|---|
| Repo | `E-Commerce-BDA/ecom-contracts` |
| Package | `@ecom/contracts` |
| First published version | `1.0.0` |
| Module format | ESM + `.d.ts` |
| Runtime dependency | `zod` peer: `>=4 <5` |
| Consumer pin | Exact version / exact release tarball URL |

`ecom-contracts` is a standalone repo. Services and frontends never import
from a sibling repo path.

## 2. Distribution

The package is distributed as a GitHub Release tarball:

```json
{
  "@ecom/contracts": "https://github.com/E-Commerce-BDA/ecom-contracts/releases/download/v1.0.0/ecom-contracts-1.0.0.tgz"
}
```

Why not GitHub Packages: GitHub Packages requires the npm scope to match the
repository owner (`E-Commerce-BDA`), which would force the package name to
change from `@ecom/contracts`. The release tarball keeps the required name,
is immutable by tag, and needs no registry scope.

## 3. Release workflow

1. PR: `pnpm typecheck && pnpm test && pnpm build`.
2. Merge to `main`.
3. Tag `v1.0.0`; the tag must equal `v` + `package.json.version`.
4. GitHub Actions runs the gates, `pnpm pack`, and creates a GitHub Release
   with `ecom-contracts-1.0.0.tgz`.
5. Consumers bump the exact tarball URL and lockfile.

No registry publish and no floating `^` ranges.

## 4. Semver rules

### MAJOR

- Remove or rename a required field.
- Change a field's type or meaning.
- Remove an enum value or change its semantics.
- Change an endpoint path, response envelope, event name, or job payload shape
  in a way that breaks an existing consumer.

### MINOR

- Add an optional field.
- Add a section type, event type, job type, or schema export.
- Add an enum value when consumers can safely ignore unknown values.
- Add a settings key to a type's allowlist.

### PATCH

- Docs, tests, comments, and internal refactors with no runtime shape change.

## 5. Consumer rules

- Pin exact versions; never `^` or `latest`.
- A MAJOR upgrade requires every consumer to re-pin in the same release train.
- `null` is never a valid override; omit the key to inherit.
- Contract changes that affect the storefront resolver require a storefront
  test update in the same release train.

## 6. Current CMS contract surface

`@ecom/contracts@1.0.0` currently ships:

- shared primitives (keys, UUIDs, hex colors, internal paths, image refs);
- CTA schema with `max(3)`;
- CMS section types and per-type content schemas;
- per-type section settings allowlists;
- `SECTION_CATALOG` admin governance rules;
- section list response and reorder schemas.

Theme, navigation, pages, blogs, media, page settings, event envelopes, and
`media.resize-image` jobs are added before the first published `1.0.0`.
